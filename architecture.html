Proposed system architecture

Each currency needs a distinct debt ledger, FX benchmark, issuance policy, liquidity pool, and risk budget. Reuse reviewed modules across currencies while keeping liabilities and backstop accounting explicit. Shared code does not require shared losses.

Modules

Module Responsibility Required boundary
Currency market Mint, burn, accrue interest, track debt No mint without authorized debt or fully funded treasury issuance
Vault engine Hold collateral claims and enforce health One recoverable claim per vault; no double counting
Collateral registry Configure reviewed assets and adapters Timelocked activation; immediate restriction of new exposure
LP adapter Value and recover managed positions External prices, actual inventory, allowed ranges, recoverable fees
FX oracle verifier Verify reports and freshness Bound reports to chain, market, source time, and sequence
Interest engine Borrower-set rates or borrowing rights Specified accrual, rounding, payment, and bad-debt behavior
Redemption engine Exchange tokens for collateral under explicit rules Oracle-valid pricing, fees, solvency limits, and no double redemption
Liquidation backstop Burn funded debt and own collateral Funded capacity separate from notional hedge exposure
LP manager Reposition authorized collateral positions Restricted targets, bounded execution, custody continuity
Keeper interface Submit reports and execute bounded work Permissionless validated actions and funded compensation

Loan entry

An LP borrower submits an authenticated FX report, buys the required stable leg, adds an eligible LP position, and locks its claim in one atomic flow. The debt engine checks conservatively valued collateral after all material state changes and mints at the chosen utilization of the permitted limit. The illustrative actual LTV is 0.95 * 0.92 = 0.874. The remaining 12.6% is collateral equity; it is not a fee or a withheld token allocation.

An ETH borrower deposits ETH and passes that branch's collateral and debt ceilings. ETH proceeds do not create the LP purchase offset. The target 4% share must be implemented as exposure headroom and an absolute cap, not a promise that future LP borrowing will restore the ratio.

Net liability accounting

When a vault's LP holds S units of its own debt token and Q units of external collateral, recovery can burn S against the vault debt D. Residual debt is D-S, subject to the actual assets recovered and any execution costs. For an 80/20 LP snapshot and debt 87.4, residual debt is 7.4 against 20 of external assets.

The position's inventory changes with every swap. Maintain current, conservative recoverable quantities; do not persist an 80/20 ratio. Other currencies' tokens are not interchangeable with the vault's debt for cancellation. Vault-level netting and system-wide reserves must reconcile without subtracting the same token balance twice.

Manageable LP positions

The initial research model uses one common narrow range. A deployable adapter must specify permitted AMMs, pool factories, token pairs, fee tiers, tick bounds, ownership, fee collection, manager permissions, and position identification. A V3 NFT is not a fungible LP token; custody and valuation must handle each accepted position or reviewed wrapper.

Only the collateral manager can move locked positions. Repositioning must retain assets in approved custody, respect execution bounds, and recheck health. A manager cannot borrow, transfer borrower equity, approve arbitrary targets, or change the collateral's token pair.

Redemptions and exits

A redemption design must identify which vault or reserve supplies collateral, which debt is burned, how LP positions are recovered, how fees are allocated, and what happens when an external asset cannot immediately settle. Providing redemptions against LP collateral is a distinct implementation task; Liquity's existing collateral recovery cannot simply be assumed to work for V3 positions.

LP withdrawal and vault closure are first-class flows. Debt repayment must release only the entitled collateral; shared positions cannot be redeemed twice. Model exits while the pool is one-sided and while the oracle or quote asset is unavailable.

Extending the system

Add a collateral type through a new reviewed adapter and parameter set, rather than arbitrary execution hooks in the core vault. The onboarding process requires independent pricing, liquidity and redemption analysis, adversarial valuation tests, and a capped pilot. Reusing the oracle-report format or vault ledger across markets is preferred where it reduces attack surface.

Design research. No production contracts or return promises. Public documentation; noindex is not access control.
