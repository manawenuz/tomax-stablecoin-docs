Security requirements and acceptance criteria

Security gates apply before capital or collateral limits increase. Production history of FiRM, Liquity, or f(x) does not establish the safety of a new FX oracle, V3 valuation, LP recovery path, or deferred settlement mechanism.

Assets and adversaries

Protect borrower collateral and surplus, stablecoin redeemability, LP positions and fees, backstop capital, report-signing keys, manager authority, and accurate debt accounting. Adversaries include flash-loan traders, MEV searchers, malicious borrowers, oracle-source manipulators, compromised publishers, unsafe collateral tokens, compromised managers, and insolvent offchain hedge venues.

The threat model must include ordinary users racing for scarce quote assets during a legitimate devaluation. A system can fail economically without a smart-contract exploit.

Economic attack cases

Test borrowing against a manipulated LP composition, submitting the most advantageous still-valid FX report, moving a range around a pending borrow, using copied sources to reach quorum, inducing an apparent USDT premium, and exploiting native-unit conversion errors. Combine these actions with collateral withdrawal, redemption, interest adjustment, and queue settlement in the same transaction and across blocks.

Stress truthful FX jumps, external quote depegs, ETH gaps, LP becoming entirely the issued token, correlated exits across currencies, keeper congestion, liquidation backstop withdrawals, and loss of an offchain hedge. Simulate full life cycles rather than entry alone.

Valuation and custody

Define the conservative recoverable value for every position state, including out-of-range and partially settled positions. Haircut delayed and uncertain claims. Never use the self-issued token's manipulable pool spot as the sole reference for its own borrowing power. Onchain inventory observation alone does not prove that accepting a manipulated inventory is safe.

Reserve held collateral for its owner until the specified liquidation transition. Control approvals and callback targets narrowly. Document manager, guardian, governance, signer, and hedge-operator powers separately, including revocation and key compromise procedures.

Verification stages

First validate economic rules with an independent integer model and adverse market paths. Then review and test each adapter, the core accounting, and complete user flows on forks of the proposed deployment chain. Require independent smart-contract review, independent economic/oracle review, remediation, regression verification, monitoring, and an incident drill before an uncapped launch.

For a capped pilot, all critical and high findings must be resolved or the affected feature disabled. Publish the accepted threat model, dependency inventory, audits, deployed code references, admin powers, and risk parameters. A multi-signature wallet or an emergency pause alone is not a substitute for these gates.

Documentation and model limitations

The supplied Python checks cover research-model conservation, range exhaustion, scaling, a failing debt mixture, and step convergence. They do not certify contracts, oracle accuracy, market demand, ETH liquidation safety, or any production deployment.

Design research. No production contracts or return promises. Public documentation; noindex is not access control.
